# Extending the Foundation

## Adding a Domain Pack

A good domain pack should include:

- problem domain
- typical modules
- typical entities
- permission patterns
- privacy risks
- security/abuse risks
- operational concerns
- compliance areas to investigate
- release gates

Avoid assuming one framework or vendor.

## Adding a Stack Adapter

Map foundation concepts to the stack:

- module boundaries
- routing
- DI/container
- migrations
- authorization policies
- jobs
- audit
- testing
- Docker/dev setup

## Adding Compliance Material

Use official primary sources where possible.

Always include:

- jurisdiction
- source
- verification date
- applicability status
- project actions

Do not copy case-specific legal advice into the generic foundation.
