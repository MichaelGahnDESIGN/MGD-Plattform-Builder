# Adopting the Foundation

## Do not copy everything blindly

The foundation is modular.

A small internal tool may not need:

- public moderation
- billing
- public profiles
- marketplace functions

A public platform may need much more.

## Adoption phases

### Phase A: Inventory

Document what exists.

### Phase B: Project Profile

Create `MGD_PLATFORM.yml`.

### Phase C: Risk Baseline

Identify personal data, privileged roles, external services, public uploads and payments.

### Phase D: Governance

Add source-of-truth docs and feature governance.

### Phase E: Technical Boundaries

Define modules, capabilities, data ownership and environments.

### Phase F: Operations

Backup, restore, staging, monitoring and deployment.

### Phase G: Release Gates

Decide what must be true before private beta, public beta and paid launch.

## Output

A good adoption does not necessarily add lots of code.

It makes the project easier to reason about and safer to change.
