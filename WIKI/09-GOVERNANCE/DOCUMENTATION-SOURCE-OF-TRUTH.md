# Documentation and Source of Truth

## Recommended layers

### README

Public orientation and quick start.

### Project Profile

Machine-readable project choices.

### Wiki / Docs

Detailed architecture and policies.

### Decision Records

Why major choices were made.

### Task System

What is currently open.

### Changelog

What changed between releases.

### Code

Technical truth of the current implementation.

## Rule

No critical decision should exist only in a chat transcript.

Move durable decisions into project documentation.

## Conflicts

When docs and code disagree:

1. investigate
2. identify current behavior
3. decide intended behavior
4. update both
5. record breaking change if relevant

## Sensitive information

Documentation must not become a secret store.
