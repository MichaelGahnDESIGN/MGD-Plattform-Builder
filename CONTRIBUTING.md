# Contributing

Thank you for considering a contribution.

The goal of this repository is to stay **project-neutral, safe, explainable and useful across different technology stacks**.

## Good contributions

- clearer architecture guidance
- additional domain packs
- privacy/security improvements
- machine-readable schemas
- stack adapters
- Docker/staging examples
- test strategies
- translation improvements
- agent compatibility
- documentation corrections

## Before opening a pull request

1. Read `README.md` and `GOVERNANCE.md`.
2. Check existing issues and pull requests.
3. Keep the change project-neutral.
4. Do not add real credentials, customer data, server addresses or private paths.
5. Do not present legal guidance as guaranteed legal compliance.
6. Update related documentation and examples.
7. Explain compatibility impact.

## Pull request checklist

- [ ] no secrets or personal data
- [ ] no project-specific brand/domain assumptions
- [ ] privacy impact considered
- [ ] security impact considered
- [ ] documentation updated
- [ ] schema/examples updated if relevant
- [ ] breaking changes called out
- [ ] links tested
- [ ] English/German impact considered

## Architecture proposals

For large changes, open an issue first and describe:

- problem
- proposed solution
- alternatives
- compatibility impact
- migration path
- privacy/security impact
- documentation impact

## Legal and compliance contributions

Prefer official primary sources. Always include jurisdiction, source URL and review date.

Do not claim that a checklist or template provides legal advice.

## Security

Do not publish active exploit details in public issues. Follow `SECURITY.md`.

## Style

- concise headings
- explicit assumptions
- examples without real personal data
- avoid hidden dependencies
- distinguish requirements from recommendations
