# Governance

## Purpose

The project is maintained as an open, reusable foundation.

## Decision principles

Changes should improve at least one of:

- portability
- safety
- clarity
- maintainability
- agent usability
- privacy
- security
- operational reliability

without unnecessarily tying the foundation to one product or stack.

## Maintainers

Maintainers decide final merge and release policy.

Contributors are encouraged to challenge assumptions with documented alternatives.

## Architecture decisions

Large architecture changes should be documented as ADR-style records containing:

- context
- decision
- alternatives
- consequences
- migration impact

## Versioning

Semantic versioning is the goal.

Before 1.0, schemas may evolve more quickly. Breaking changes must still be documented.

## Compatibility

The foundation distinguishes:

- normative core principles
- recommended patterns
- optional packs
- stack-specific reference implementations

A stack adapter may differ technically without violating the core principles.

## Legal content

Compliance documentation is versioned research support, not legal certification.

Country- or sector-specific contributions must identify their jurisdiction and review date.
